# Outbox review, export and editing

This continuation completes the local management loop around the
[durable foreground Outbox](outbox.md). It uses the same account-owned SQLite
repository for native IMAP/SMTP, EWS, Gmail and Microsoft 365. All controls and
feedback are available in English, German and Arabic.

## Review and export

Open **Outbox**, then **Review message**. The dialog shows the saved subject,
sender, To/Cc/Bcc, Message-ID/date, body text, attachment names/types/sizes,
submission state and attempt count. It does not invoke a provider, render HTML,
open attachments or load remote resources. Long bodies have an explicitly
shortened preview; editing and export retain the complete admitted content.

**Export EML** saves the original frozen MIME bytes, including encoded
attachments, Date, Message-ID and boundaries. It never serializes the preview.
Messages generated by the supported composer omit Bcc headers; exact export of
older or unsupported MIME preserves any existing headers. **Export private
recipient record** separately confirms and saves JSON with the complete transport sender
and recipient list, original wire SHA-256, decoded message identifiers when
available, state and attempt information. This file contains hidden recipients;
share it deliberately. It contains no account/profile key or credentials.

Exports use a native file picker, stage and flush the full file in the chosen
directory, and refuse an existing file or symlink. Choose a new filename if it
already exists. Cancelling a picker writes nothing. Disposal and session checks
guard the picker and prepublication boundaries. An export failure leaves the
Outbox message unchanged.

## Edit a queued message

**Edit as new draft** is available for queued messages and definite retryable
failures only when no earlier attempt may have been accepted. The confirmation
explains that the original queue entry will be cancelled and retained.

The host first durably saves its current selected draft. It then reconstructs
the supported composition from the frozen MIME and recipient envelope, validating
the full MIME structure, sender, To/Cc ordering, hidden recipients, threading and
all attachments. The SQLite handoff is one transaction:

1. Compare the complete persisted original snapshot, including state and attempt.
2. Cancel that original queue entry without changing its frozen bytes.
3. Admit a new, distinct revision-zero draft, with its own ID and immutable
   attachment ownership, inside the same quota and active-draft checks.

Failure rolls back both changes. Another send/edit cannot race into two
sendable copies. The source draft's cleared revision marker is never resurrected,
and unrelated drafts remain intact. Only after commit does the adapter change
the selected ID/epoch. The host consumes the returned snapshot directly before
opening the ordinary Word composer; old callbacks cannot overwrite it.

The supported composer is plain text with its generated escaped HTML alternative
and ordinary files. Editable CRLF line endings are normalized to LF; raw message
bytes and the parsed original remain unchanged. Custom HTML, extra body parts,
inline relationships, unsupported headers, incomplete parses and unsupported
attachment metadata are refused rather than silently discarded. Exact EML and
private-envelope export remain available even if projection is refused.

Saving or closing the new draft never sends it. A later explicit Send or Queue
creates a new frozen message with fresh Date/Message-ID/MIME boundaries. A retry
of the old frozen entry still uses its existing bytes; cancelled originals have
no retry control. Copying accepted, submitting or uncertain entries into a
resendable draft is not part of this action.

## Stop retrying while delivery remains unknown

An uncertain record, or a later failure carrying older uncertainty, offers
**Stop retrying**. Confirmation records **Closed locally — delivery unknown**.
This is a new terminal local state, not a synthetic provider result. It preserves
the original MIME/envelope, latest outcome, attempt identity/count and earlier
uncertainty. It can also close a legacy inherited uncertainty with no new Outbox
attempt. It cannot close a live submitting attempt.

The closed entry has no send/retry/edit path. Review and exact export remain
available. **Remove local record** uses a separate confirmation explaining that
delivery is still unknown and removal deletes the local message and attempt
information. Neither closure nor removal recalls mail, deletes a server copy,
proves failure or establishes delivery. Users who still intend another send must
continue using the existing acknowledged uncertain-retry path before closure.

## Storage and acceptance boundaries

Existing queued records remain readable without a destructive schema migration.
The added state is validated by the core model and storage codec; invalid
closure, stale compare-and-set, revived terminal records and changed frozen
payloads are refused. Earlier builds do not understand the new state and are not
a supported downgrade path for a profile containing it.

The existing 100-entry Outbox and 100-active-draft admission limits remain.
The composer retains its 1 MiB plain body, ten attachments/10 MiB total, and
22 MiB generated-wire bounds. Projection uses fixed cumulative decode, body,
part-count and nesting limits; callers can tighten but cannot enlarge them.

This remains a local, native, foreground workflow. Reconnect the same account to
inspect its Outbox after restart. The limited offline draft workspace is separate
and does not expose an offline Outbox or cached inbox. No actual user mail or
credentials are used in qualification. Local fixtures establish the recorded
cases, not arbitrary power-loss durability or delivery by live providers.
