## Reproduce

Use the pinned SDK and an enforced lockfile. Native tests require the real
package-hook-generated SQLite mapping; the runner records it and rejects
shadowing package-local mappings.

```sh
python tools/mail/check_store.py --flutter-sdk /path/to/flutter   --offline --direct-tests --command-timeout 600 --output /path/to/store-results
python docs/validation/mail-offline-accounts-20261120/run_host_checks.py   --flutter-sdk /path/to/flutter --phase broad --output /path/to/broad-results
python docs/validation/mail-offline-accounts-20261120/run_host_checks.py   --flutter-sdk /path/to/flutter --phase mail-final --output /path/to/mail-results
python docs/validation/mail-offline-accounts-20261120/run_host_checks.py   --flutter-sdk /path/to/flutter --phase office-final --output /path/to/office-results
```

## Remaining qualification and product boundaries

These are native synthetic-provider/storage tests. They do not establish live
provider interoperability, installed desktop/mobile packaging or browser storage
execution. Compilation and Node execution are recorded separately from those
open gates. Local files remain unencrypted under the existing host policy.

This increment provides offline local draft composition after one verified
connection. It does not provide a cached/unified offline inbox, durable mailbox
sessions, provider Drafts synchronization, offline Outbox management or automatic
sending. The next ordered boundary is repository-backed account/folder state
and durable sync commands, then provider Drafts synchronization with explicit
conflicts. Rich HTML, signatures/templates, undo-send and scheduling remain
separate composition/sending work.
