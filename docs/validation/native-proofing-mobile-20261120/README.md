# Native proofing libraries on iOS/iPadOS and Android — 20 November 2026

**Result:** all five optional native backends build for iOS and Android,
are packaged the way the stores require and pass an on-device gate on the
iOS Simulator and an Android emulator. The Studio app loads each one through
its own host code. Pinned data is downloaded into the app's private sandbox.
spaCy matches the frozen development panel exactly on both. The Android arm64
spaCy library is now recorded for **analysis only**. No mobile build is
qualified for grammar, and the planner gate is unchanged.

## Packaging

| | Android | iOS / iPadOS |
| --- | --- | --- |
| Form | `lib<name>.so` per ABI: arm64-v8a (devices) and x86_64 (emulator). NDK 28.2, API 24, static libc++, 16 KB page alignment, stripped by the build. | Dynamic framework `<name>.framework/<name>` with install name `@rpath/<name>.framework/<name>`. One XCFramework holds an arm64 device slice and an arm64+x86_64 simulator slice (lipo), with minimum iOS 13. |
| Build | `tool/build.py --android [--android-abi …] --install-android <jniLibs>`. The shared helper is `tools/proofing/mobile_native.py`, and Harper uses cargo with the NDK linker. | `tool/build.py --ios --install-ios ios/QudsProofingNative/Frameworks` |
| Host | `android/app/src/main/jniLibs/<abi>/` (git-ignored). `useLegacyPackaging` extracts the libraries, and `keepDebugSymbols` keeps the spaCy library byte-exact. | The vendored CocoaPods pod `ios/QudsProofingNative` embeds the frameworks, and the app build signs them. No loose dylibs. Run `pod install` after adding or removing a framework. |
| Dart loader | `DynamicLibrary.open('lib<name>.so')`, resolved from the APK's native library directory | `Runner.app/Frameworks/<name>.framework/<name>` (Studio host) or the package default `<name>.framework/<name>` |
| Data | `getApplicationSupportDirectory()`, which is `Context.getFilesDir()`: `/data/user/<n>/<pkg>/files/quds_office_studio` | The sandbox container's `Library/Application Support/quds_office_studio` |

spaCy: Android loads `libcrispembed-spacy.so`. iOS loads
`crispembed_spacy.framework`, because CocoaPods cannot link a vendored
framework whose name contains `-`. The Studio host measures the shipped
file's SHA-256 (and, on iOS, the signature-independent code digest when the
binary is thin) and re-verifies it before every load. Qualification is looked
up by those digests.

Build receipts for the exact tested bytes are in [receipts/](receipts). The
spaCy receipt is `build-receipt-mobile.json`, separate from the macOS receipt.

## Gate

`packages/quds_office_editor/example/integration_test/mobile_native_proofing_test.dart`
runs through the Studio host code and prints one `QUDS_NATIVE_GATE` JSON
line. The sanitized lines are in
[ios-simulator-gate.json](ios-simulator-gate.json) and
[android-emulator-gate.json](android-emulator-gate.json).

| Check | iOS Simulator (iPhone 16, iOS 18.6, arm64 slice) | Android emulator (Pixel 6, Android 16 / API 36, arm64-v8a) |
| --- | --- | --- |
| Private data directory inside the sandbox, writable | pass (container `Library/Application Support`) | pass (`/data/user/0/<pkg>/files`) |
| Hunspell: AyaSpell downloaded, verified and installed in the sandbox; `ذهبت البنت الى المدرسه وقالت هاذا جميل` flags exactly `الى`, `المدرسه`, `هاذا`; first suggestion `إلى` | pass | pass |
| Arabic morphology: proofing-bin downloaded; `كتبوا` gives lex `كَتَب`, verb, plural | pass | pass |
| CLD3: German `de` (0.999995), Arabic `ar` (0.997445) | pass | pass |
| Harper: `This is an test.` gives `harper.AnA`, `an` → `a` | pass | pass |
| spaCy de: model downloaded to the sandbox, 16-case development panel, 113 tokens, 22 sentences, 2,571 fields exact | pass, 0 differences | pass, 0 differences |

Commands (simulator and emulator driven only from the CLI):

```sh
xcrun simctl create quds-gate-iphone "iPhone 16" com.apple.CoreSimulator.SimRuntime.iOS-18-6
flutter test integration_test/mobile_native_proofing_test.dart -d <simulator udid>
avdmanager create avd -n quds-gate -k "system-images;android-36;google_apis_playstore;arm64-v8a" -d pixel_6
flutter test integration_test/mobile_native_proofing_test.dart -d emulator-5554
```

The development panel is embedded in
`integration_test/spacy_development_cases.g.dart`, generated by
`tools/proofing/spacy/mobile_development_cases.py`. The VM test
`test/spacy_development_cases_test.dart` re-derives it from the
authenticated fixtures (manifest `9a3bb6ba…` and per-case SHA-256), so the
copy cannot drift. The comparison is the same per-field comparison that
`tool/replay_development.dart` makes.

## spaCy mobile qualification status

- **Android arm64-v8a** `ed730f62…` (the stripped library shipped byte-exact
  in the APK): analysis parity is recorded in `spacyRecordedBuilds` as
  `spacyAndroidArm64BundledSha256`. The record is analysis only, and grammar
  is refused because the digest is not in `spacyGrammarNativeSha256s`.
- **Android x86_64**: built. It was not run, because the only system image on
  this Apple-silicon host is arm64, and x86_64 images do not run there. It is
  unrecorded.
- **iOS**: the simulator slice passed the same parity check. The device slice
  (`ios-arm64`, receipt `2a0ca967…` before app signing) was not run on a
  device, so iOS has no recorded claim. The simulator slice is a fat
  arm64+x86_64 binary, which `machOCodeSha256` rejects by design, so it cannot
  carry a signature-independent record either. Analysis still runs (the host
  offers analysis for unrecorded builds). Grammar is refused.
- **Grammar** on mobile was not attempted. It needs the full W6/W7/v2 panel
  replay (`tool/replay_grammar_panels.dart`) on the exact binary on a device.
  Those panels read repository fixtures that are not yet packaged for an
  on-device run. The numerical stage traces, ctest and C text-API controls
  that back the desktop records were not run on mobile either.

## Not verified here

- Physical devices (no iPhone or Android hardware was attached). Device
  signing with a distribution identity happens in the app build. For the
  spaCy device slice, the code digest would survive re-signing (thin arm64).
- The full Studio UI on mobile. The gate exercises the hosts and packages,
  not the editor's mobile layout.
