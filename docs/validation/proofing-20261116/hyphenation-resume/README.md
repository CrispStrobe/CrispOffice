## Changes covered

A selected hyphen now has explicit `displayText: '-'` presentation metadata.
That isolates it from authored paint runs while preserving its original source
ownership: zero UTF-16 units for automatic hyphens, one for U+00AD. Painting no
longer substitutes the next source letter for an automatic hyphen or hides the
selected U+00AD. Logical line text and PDF ActualText retain the authored text.
The final non-BMP character of a paint run is reconstructed as a full scalar.

Header and footer overlays retain the original paragraph and exact UTF-16
mapping after trimming and tab-column extraction. Repeated labels are mapped
by sequential source position. Generated fields/page numbers and presentation
join spaces have null ownership. The final overlay boundary is recorded where
unambiguous.

The column-layout regression now identifies body lines by paragraph identity;
`sourceText == null` is no longer a valid body-line discriminator because body
lines carry their original source text.

The editor regression run initially exposed a debounce timer that survived a
view detaching from an external controller. View ownership now attaches and
detaches independently of explicit host-started checking. The complete editor
suite was rerun after that lifecycle repair.

## Reproduction

From `packages/quds_office_engine`, run the command recorded in
`engine/hyphenation-validation.json` (or `python3
tool/proofing/validate_hyphenation.py --dart <dart> --output <evidence-dir>`).
From `packages/quds_office_editor`, run:

```sh
flutter test --no-pub test/word_hyphenation_paint_test.dart \
  test/word_note_numbering_test.dart test/word_small_caps_test.dart \
  --reporter expanded
```

Use the resolved workspace dependencies and a writable temporary directory.
The exact SDK paths, commands, base commit and source/log digests are recorded
in the receipts. Browser painting and device execution are outside these runs.
